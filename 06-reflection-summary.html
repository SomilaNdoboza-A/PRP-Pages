REFLECTION / LEARNING & DEVELOPMENT

KasiBook Reflection Summary

A personal reflection on the technical, teamwork and professional learning gained through the KasiBook Entrepreneurial WIL project.

Project reflection

KasiBook gave me an opportunity to apply software development concepts to a problem that affects small businesses in township communities. The project focused on reducing the difficulty of managing bookings and orders through informal channels such as WhatsApp messages, phone calls and notebooks. Working on a solution with a clear user and business context helped me think about software in terms of the problem it needs to solve, rather than only the technologies used to build it.

As the Backend and Database Lead, my responsibilities included backend development and API design, SQLite database design and connectivity, authentication, and connecting the frontend to backend services. This role helped me understand how important data structure and reliable communication between application layers are to the overall user experience. A screen can look complete, but the feature is not complete if the information is not stored or processed correctly.

What I developed

  • Technical understanding: A stronger understanding of how backend logic, APIs and a relational database support user-facing functionality.
  • Planning: Experience breaking a product idea into user stories, prioritised backlog items and sprint-level work.
  • Collaboration: Experience working with a three-person team where design, frontend, backend and testing responsibilities depended on one another.
  • Quality mindset: An appreciation that testing, documentation and integration checks are part of completing a feature.
  • Professional practice: The importance of communicating progress, raising blockers and keeping project evidence organised.

Challenges and areas to improve

One of the main challenges in a project with separate frontend and backend responsibilities is ensuring that components connect as expected. Dependencies between UI decisions, API requirements and database structure need to be discussed early. I would improve future projects by agreeing on API contracts and data structures earlier, keeping acceptance criteria measurable, and using smaller integration checks throughout development instead of waiting until the end.

I would also improve the quality of my project records. A logbook should be updated while work is happening, and testing should be documented with the test case, expected result, actual result and any corrective action. This makes it easier to demonstrate what was done and to learn from defects.

How this connects to my development goals

KasiBook reinforced my interest in software engineering, particularly backend development, database design and building complete applications. It gave me a practical reason to keep developing my JavaScript, SQL, API and application architecture skills. Going forward, I want to strengthen my testing practices, write clearer technical documentation and build software that is maintainable as well as functional.

Reflection

This reflection brings together what I learned from the project rather than repeating the task list. My main takeaway is that software engineering is collaborative and iterative. My backend and database work had to support the screens and workflows the rest of the team was building. I became more aware of the importance of planning interfaces between components, testing early, and recording decisions and outcomes. These are practices I want to carry into future academic and professional software projects.
